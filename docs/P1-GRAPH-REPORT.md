### DAG 泳道算法（核心）

输出模型从「穿行泳道集合」升级为**显式连线段**：

```rust
pub struct LaneSegment { pub from_lane: u32, pub to_lane: u32 }
```

- `from_lane == to_lane` → 竖直连线
- 不同 → 父提交在别的泳道，画斜线/曲线

算法不变式（写进注释与测试）：
1. `active[i] = Some(oid)` 表示第 i 条泳道正在等待 oid 出现
2. **第一父提交总是占用本行泳道**，即使已被登记 —— 否则兄弟提交会挤进同一泳道
3. 其余父提交（合并）若已被登记则直接连过去，不再分叉
4. 汇合时保留编号最小的泳道，其余泳道画出汇入斜线

**9 个算法测试**覆盖：线性历史、分支分叉、合并提交、章鱼合并（3 父）、三头并行、共享父提交、泳道紧凑复用、根提交终结、空输入。

## 关键设计决策

1. **算法与渲染解耦**：泳道计算在 Rust 端完成并单测钉死，前端只负责按坐标画线。这样换渲染方案（Canvas/WebGL）不影响算法。
2. **历史 diff 复用工作区 diff 的数据结构**：两者都是 `FileDiff`，前端共用 `DiffViewer`，不必维护第二套渲染逻辑。
3. **通过 `area` 字段区分按钮显示**：历史 diff 的 `area` 是 `staged` 但缺少操作回调，因此不显示暂存按钮。
4. **未实现的功能显式置灰**：分支 / Stash / 标签 / 远程在左栏可见但置灰，点击提示「下一阶段实现」，让用户知道路线图而不是找不到入口。

## 当前限制（诚实说明）

- **分支 / Stash / 标签 / 远程**：左栏已列出但尚未实现，点击会提示
- **终端**：仍是占位
- **冲突解决**：无三方视图
- **提交图交互**：只能点选查看，尚不支持右键菜单（checkout / cherry-pick / reset 等）
- **大仓库**：虚拟滚动已实现，但 `read_history` 一次性取出全部 oid 再分页，超大仓库（10 万+ 提交）首屏可能慢，后续可改游标分页
